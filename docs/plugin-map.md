# Plugin map

Each file in the plugins and what it does. animal-writes-core, Kits Core and SourceWeb load from `animal-writes-core/animal-writes-core.php` (Kits Core is required first, SourceWeb last; either may also be active on its own and is then not loaded twice); MailWeb (`mailweb`), `aw-seo-extras` and InsightWeb (`insightweb`) are separate plugins. Forms: see `how-to-change-a-form.md`.

Plugin names and update source (owner, 10 Nov 2026): `aw-seo-extras` is RankWeb, `mailweb` is MailWeb, `aw-sourcing` is SourceWeb, `insightweb` is InsightWeb (Search Insights, out of RankWeb on 11 Nov 2026); folders, files, text domains, options, REST routes, cron hooks and menu slugs kept their old names. All five of our plugins carry an `Update URI` header (`https://wugweb.com/plugins/<folder>/`: `aw-seo-extras`, `mailweb`, `aw-sourcing`, `kits-core`, `animal-writes-core`), so WordPress never offers a WordPress.org plugin of the same name as an update.

Edit screens (every box, its fields, stored keys and where they are used): see `edit-screens-map.md`.

## Plugin Check (13 Nov 2026)

The Deploy check runs Plugin Check (`wp plugin check`) on each of our seven plugins that changed in a push; an error fails it, warnings are printed (`tools/ci/smoke.sh`). Three codes are accepted and passed to `--ignore-codes`:

- `plugin_updater_detected`: the `Update URI` header stays on our plugins (owner, 12 Nov 2026).
- `PluginCheck.CodeAnalysis.Offloading.OffloadedContent`: the Leaflet and MapLibre map libraries load from a CDN (`map-picker.php`, `directory-map.php`); bundling them in the plugin waits for the owner.
- `WordPress.WP.I18n.TextDomainMismatch`: DirectoryWeb's strings inside Animal Writes Core use the `directoryweb` domain, for the day DirectoryWeb is its own plugin.

Still open as warnings: the `aw_` prefix is 3 characters (Plugin Check asks for 4 or more; about 2,850 warnings), and database calls with the plugin's own table names (`UnescapedDBParameter`).

## Capabilities (13 Nov 2026)

Each Wugweb plugin has its own capability. Each plugin grants it on activation and once after an upgrade (option `<plugin>_caps`), to administrator and to every role that holds the old capability. Until that has run, a `user_has_cap` filter gives the new capability to anyone who holds the old one, so nobody loses access. No capability is taken off any role. Settings screens keep `manage_options`.

## Backup before uninstall deletes (13 Nov 2026)

When "Delete this plugin's data when it is deleted" is ticked, each of the seven plugins' `uninstall.php` first writes `wp-content/uploads/wugweb-backups/<plugin-slug>-uninstall-<YYYYmmdd-His>.jsonl.gz` (UTC) with its own `includes/uninstall-backup.php` (identical in each plugin apart from the function prefix): a header line (plugin, version, site, time, the options and tables in the file), one line per option to be deleted (`option_value` exactly as stored, with `autoload`), then one line per row of each table to be dropped, read 500 rows at a time. Values that are not valid UTF-8 are base64-encoded and named in `b64`. Transients are not kept. The folder gets `index.php` and an `.htaccess` "Require all denied". The file is written as `.part` and renamed when complete; if the folder, `gzopen`, a read or a write fails, one line goes to the PHP error log and nothing is deleted.

## Three areas, three owners (owner, 31 Oct 2026)

Search Insights, Sourcing and Classification are separate areas. A change belongs to the area that owns the screen and the logic, not to the area whose data it reads.

| Area | Plugin and menu | Owns | Reads, never edits |
|---|---|---|---|
| **Search Insights** (search demand and site performance) | `insightweb` (InsightWeb), RankWeb → Search Insights (Overview, Keywords, Rising, Pages, Links, Check list, Settings) | Search Console, GA4 (incl. referrals), PageSpeed, Clarity, Bing Webmaster, the rising-terms job and its spikes, the Links view, the crawler-access check, the keyword table's Search Insights roles and figures, the monthly snapshot | Sourcing's items and counts (News spikes, per-keyword items), Rank Math keyphrases |
| **Sourcing** (what the workers fetch and how it arrives) | `aw-sourcing`, Sourcing menu (Overview, To review, Enrichment review, Sources, Keywords, Rules, AI models, Workers, reports, Settings) | Feeds and publishers, relevance keywords, rules and summaries, AI models, auto-review, Directory enrichment, the workers' endpoints and the Workers tab | Search Insights' searches (only as suggestions in Keywords → Suggestions; never added automatically) |
| **Classification** (how content is organised on the site) | `animal-writes-core`, Classification menu (Categories, Tags) and the content types | Categories, tags, sections, the content model | Nothing from the other two |

Where they meet, the line stays: the keyword table is Kits Core's (`kits-core/includes/keyword-table.php`, from Core 12 Nov 2026), and each area writes only its own roles. Search Insights → Sourcing keywords (`aw-sourcing/includes/search-insights-tab.php`) is Sourcing's code shown inside Search Insights. Sourcing → Keywords → Suggestions only reads Search Insights.

### Social posts routes (workers contract, 2 Nov 2026)

Both routes: the workers' application-password user (`aw_worker` capability) or an administrator, the same check as `aw/v1/search-insights`. While Kits → Modules → Social posts type is off, both answer **409** `{"code":"aw_social_off"}`.

**GET `/wp-json/aw/v1/social/campaigns`**: one entry per published campaign whose "Hashtags and search strings" box is filled.

```json
[{"slug": "campaign-lab-animals-2026", "title": "Object to the draft lab animal rules 2026", "terms": ["#Tag", "\"a phrase\""]}]
```

`slug` is the campaign's own `aw_campaign_link` term (send it back as `campaign`); `""` when the campaign has none. `terms` keeps the lines as typed (at most 50, 100 characters each).

**POST `/wp-json/aw/v1/social/intake`**: at most 200 items per call.

```json
{"items": [{"url": "https://x.com/name/status/123", "platform": "x", "author": "Name", "handle": "@name", "date": "2026-11-02T08:15:00Z", "format": "video", "campaign": "campaign-lab-animals-2026", "metrics": {"views": 1200, "reposts": 30, "likes": 210, "replies": 12, "seen_on": "2026-11-02"}}], "dry_run": false}
```

- `url` is required; the rest is optional. `platform` is read from the link for X, YouTube and Bluesky (else the value sent: x, youtube, bluesky, mastodon, instagram, facebook, linkedin, other). `date`: `Y-m-d`, or a time (a time without a zone counts as UTC), stored as the IST day. `format`: video, picture or text (words like reel, photo are mapped). `campaign`: one slug or a list; only existing `campaign-*` terms are linked, others are ignored. `metrics`: whole numbers; `seen_on` defaults to today when any number is sent.
- No post text is accepted: the summary is written by staff.
- Every new record is **pending** (Sourcing → To review); nothing is published. Duplicates (same post, in any status including Trash, or twice in one call) are skipped.
- Answer (201 when something was created, else 200):

```json
{"dry_run": false, "received": 1, "created": 1, "would_create": 0, "duplicate": 0, "invalid": 0, "items": [{"status": "created", "id": 24001, "url": "https://x.com/name/status/123"}]}
```

`status` per item: created, would_create (dry run), duplicate (`id` is the saved record), invalid (`message` says why). 400 when `items` is missing, empty or longer than 200.

Removed on 25 Oct 2026 (code clean-up; git history keeps them): the site's own forms and their public handlers (`admin-post.php` actions aw_newsletter, aw_volunteer, aw_claim, aw_report, aw_contact, aw_remove_data; Fluent Forms is the only form), `newsletter-optin.php` (the old forms' newsletter box), the WP-CLI commands `aw ff-off`, `aw crm-import`, `aw crm-move`, `aw vol-to-crm`, `aw nl-form`, `aw nl-import-volunteers`, and the shortcodes no page or template used ([aw_volunteer_form], [aw_claim_box], [kits_endbar], [aw_rel_time], [aw_issuer_label], [aw_org_links], [aw_place_links], [aw_trust], [aw_stats], [aw_browse_states]). Then (cleanup 2): the CSS and JS only those served (`kit-endbar`, `kit-trust`, `aw-stats`, `kit-filter-group` and "Show more", the old footer newsletter and volunteer form rules, aw.js code for the old forms) and their kits-registry entries.
